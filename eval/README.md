# Hand-labelled evaluation

The pipeline has never been checked against human labels. The `ai/data/raw` folder names were
generated by an older colour heuristic (see `archive/circular_eval/README.md`). This folder
holds a small, honest test set that **you label by hand**.

## 1. Get the images
```bash
python scripts/eval.py sample --source ai/data/raw --n 40
```
This copies 40 images (balanced across the light/medium/deep folders) to
`ai/data/eval_images/` as `img_001.jpg …`. The neutral names mean you label **blind**,
without seeing the old folder labels. `eval/labels.csv` is already created with one blank
row per image.

The original paths, and how each image was chosen, are in
`ai/data/eval_images/manifest.csv`. **Don't open it while labelling:** the paths contain
the old heuristic folder names.

The images are git-ignored (dataset licence), so a fresh clone needs its own sample.

## 2. Label them (`eval/labels.csv`)
| column | allowed values |
|---|---|
| `depth` | `light`, `medium`, `deep` |
| `undertone` | `warm`, `neutral`, `cool`, `olive`, or `unsure` (excluded from scoring) |
| `labeler` | your initials |
| `notes` | anything odd: heavy makeup, coloured lighting, filter, face partly hidden |

Tips for useful labels:
- Judge the **skin**, not the lighting. If the photo's lighting makes it impossible, write `unsure`.
- Undertone from a photo is genuinely hard, even for people. `unsure` is a valid answer, and
  better than a guess.
- If you can, have a second person label the same 40 images independently. The rate at which
  you two agree is the realistic ceiling for any automatic method.
- Check the label balance once you're done (the `run` output prints it). If one class has
  fewer than ~5 images, the per-class numbers mean little.

## 3. Top up rare classes
After labelling everything (use `unsure` where you can't tell), make sure each undertone
class has enough examples:
```bash
python scripts/eval.py topup --min-per-class 8
```
If any class has fewer than 8 labels, this adds more images to `labels.csv` as new blank
rows. Label them, then run `topup` again until it says nothing is needed.

How it picks images, and why that's still fair:
- True undertone is unknown until you label, so for each short class it picks random
  images **that the pipeline predicts** as that class (about 2 per missing label).
- That would flatter the pipeline's recall on those classes, so `run` uses these
  "targeted" images **only for precision** ("when it says olive, how often is it right?"),
  where they're a fair random sample. Recall, overall accuracy and the confusion matrix
  use only the initial and random images.
- To keep you blind, the same number of purely random images is mixed in and everything
  is shuffled. Only the total is printed.
- The pipeline predicts very few images as olive (about a dozen in the whole pool), so
  olive may not reach 8 from this dataset. `topup` says so if a class runs out of
  candidates. Photos from another source would be needed.

## 4. Score
```bash
python scripts/eval.py run
```
For depth and undertone this prints:
- **overall accuracy** with a 95% confidence interval
- **per-class accuracy (recall):** of the images you labelled *olive*, how many the
  pipeline also called olive, with its own interval. Also **precision**: of the images
  the pipeline called *olive*, how many you labelled olive.
- **balanced accuracy:** the mean of the per-class recalls. A model that always says
  "cool" can get high overall accuracy if most images are cool, but its balanced accuracy
  is only 1/k. Quote this when classes are unbalanced.
- the confusion matrix, and two baselines:
- **majority-class**: always predict the most common label in *your* labels
- **random**: 33% for depth (3 classes), 25% for undertone (4 classes)

The pipeline is only useful where it clearly beats both. With n≈40 the overall interval is
about ±15 percentage points, and with 8 images per class the per-class intervals are about
±30, so report them alongside the numbers. Classes with fewer than 5 labels are flagged
"too few to judge".

## 5. Lighting stability (no labels needed)
```bash
python scripts/eval.py stability
```
Re-runs each photo with exposure ±0.5 EV and warmer/cooler light, and reports how much the
measured colour (ΔE00), ITA, depth and undertone change.
